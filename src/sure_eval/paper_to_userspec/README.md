# Paper_to_UserSpec Agent

Paper_to_UserSpec is the SURE pre-agent that converts a paper PDF or paper text into an evidence-backed `user_spec_query.json` and a route-specific draft such as `MODEL_INPUT.yaml`.

It does not reproduce the paper, clone repositories, download weights, scan GitHub/HuggingFace/ModelScope, run inference, run benchmarks, train models, compute a resource audit, or produce a final reproducibility score.

## Scope

The MVP owns only Stage 0 and Stage 1:

1. Parse or canonicalize the paper input.
2. Extract a conservative user spec from paper evidence.
3. Convert paper spans to `paper_evidence_cards.jsonl`.
4. Compute paper-only confidence.
5. Route the draft.
6. Validate the generated artifacts.

Optional CLI inputs:

```bash
--repo-url https://github.com/owner/repo
--model-card-url https://huggingface.co/owner/model
```

These user-provided URLs can help routing and can count as user-provided evidence for `source.repo_url`. They do not trigger any repo or model-card scan.

## Build

```bash
PYTHONPATH=src python -m sure_eval.paper_to_userspec.cli build \
  --case-id <case_id> \
  --paper-text local_inputs/papers/<case_id>/paper.txt \
  --goal onboard \
  --out runs/paper_to_userspec/<case_id>
```

For PDF input:

```bash
PYTHONPATH=src python -m sure_eval.paper_to_userspec.cli build \
  --case-id <case_id> \
  --paper local_inputs/papers/<case_id>/paper.pdf \
  --pdf-parser pypdf \
  --goal onboard \
  --out runs/paper_to_userspec/<case_id>
```

`--paper` and `--paper-text` are mutually exclusive. PDF parsing is local. If parsing fails, rerun with extracted text through `--paper-text`.

## Default Outputs

Default build writes at most eight files:

```text
runs/paper_to_userspec/<case_id>/
├── user_spec_query.json
├── MODEL_INPUT.yaml                         # route = tool_onboarding
├── validation_report.json
├── paper_confidence_report.json
├── paper_evidence_cards.jsonl
├── README.md
├── canonical_paper.md
└── paper_parse_report.json
```

For routes other than `tool_onboarding`, the route-specific file may be `MAIN_FLOW_INPUT.yaml`, `training_conversion_request.json`, or `missing_information_request.json`.

## Debug Outputs

Pass `--debug-artifacts` to also write parser/debug intermediates:

## Paper Confidence

`paper_confidence_report.json` is paper-only. It asks whether the paper text contains enough evidence to create a trustworthy SURE input draft.

It scores only:

- paper evidence for `model.name`
- paper evidence for `task.primary_task`
- paper evidence or user-provided evidence for `source.repo_url`
- paper evidence for `source.model_card_url`
- paper evidence for `evaluation.metrics`
- paper evidence for `data.eval_datasets` / `data.downstream_datasets`
- section coverage across title, abstract, method, experiments, and results
- declared availability in the paper text

Declared availability is not verification. A paper statement such as code available at GitHub can set `declared_code_available`; a checkpoint/weights availability statement can set `declared_checkpoint_available`; HuggingFace or ModelScope evidence can set `declared_model_card_available`.

## Non-Goals

Default build does not output:

```text
resource_audit_report.json
resource_evidence_cards.jsonl
final_reproducibility_score.json
final_evidence_cards.jsonl
final_reproducibility_report.md
external_evidence.json
repo_summary.json
model_card_summary.json
review_summary.json
```

Those belong in a future ResourceAuditAgent or a separate reproducibility-scoring agent.

## Validation

```bash
PYTHONPATH=src python -m sure_eval.paper_to_userspec.cli validate-model-input \
  --input runs/paper_to_userspec/<case_id>/MODEL_INPUT.yaml
```

## Two-Stage Design

1. **Stage 1 — Confidence (paper-only)**
   - `paper_confidence_report.json` is generated by the `build` command.
   - It is purely paper-derived and requires no external audit.

2. **Stage 2 — Report1 (confidence + external audit)**
   - `report1_screening_report.json` is generated only when an external audit has been completed.
   - Running `report1` without a checked audit will fail fast with a clear message.

## Report1: Pre-SURE Screening

Report1 requires a completed external audit. You can obtain one in two ways:

**Option A — Run the lightweight external collector:**

```bash
PYTHONPATH=src python -m sure_eval.paper_to_userspec.cli report1 \
  --input-dir runs/paper_to_userspec/<case_id> \
  --output-dir runs/paper_to_userspec/<case_id> \
  --enable-external-audit \
  --online
```

**Option B — Provide pre-collected external evidence:**

```bash
PYTHONPATH=src python -m sure_eval.paper_to_userspec.cli report1 \
  --input-dir runs/paper_to_userspec/<case_id> \
  --output-dir runs/paper_to_userspec/<case_id> \
  --external-evidence-json path/to/external_evidence.json
```

After a successful audit, Report1 writes:

```text
report1_screening_report.md
report1_screening_report.json
report1_evidence_trace.jsonl
report1_external_resource_audit.json
```

Offline runs (without `--enable-external-audit --online` and without pre-collected evidence) stop after confidence and do **not** produce an official Report1.
