# Memory Routing

This file controls optional memory selection for the model tool-agent. The goal
is to keep default context small while still making hard cases discoverable.

## Always Read

- `memory/COMMON.md`
- `task_playbooks/ROUTING.md`
- `playbooks/env_ROUTING.md`
- `<run_dir>/artifacts/memory_context.json` when it exists: the `pre_start` hook
  writes it with the memory facts that match this run (cluster, model family,
  datasets). Read it once during `context_selection`; it is advisory.

## Read Only On Trigger

| Trigger | Read | Why |
|---------|------|-----|
| Validation or build fails with a known error class | `playbooks/failure_taxonomy.md` | Classify the failure before retrying. |
| Retry decision is needed | `policies/retry_and_escalation.md` | Decide retryability and stopping conditions. |
| Patch to upstream/runtime/config is proposed | `policies/patch_recording.md` | Ensure patch reason and scope are recorded. |
| Host capability, GPU, Docker, registry, network, or TMPDIR risk is relevant | `playbooks/preflight_checklist.md` | Run targeted preflight checks. |
| Input is generated by XForge bridge | `playbooks/xforge_sure_bridge.md` | Follow scaffold and artifact expectations. |
| Error resembles a known bad case | `sure/memory/index.md` first (repo-root path; merged index of legacy, confirmed and provisional entries, one bullet per entry with its triggers), then the matching entry file | One lookup covers every layer; `memory/bad_cases/README.md` only lists exported entries. |
| A gate repair ends with a `Memory (advisory, ...)` block | the entry files named in that block | The hook already matched them to this unit and this error. |

## Bad Case Routing

Bad cases are not default context. A bad case requires both:

1. an observed symptom or error string; and
2. a matching bullet in `sure/memory/index.md` (a trigger that is a substring
   of the error, case-insensitive) or a matching row in
   `memory/bad_cases/README.md`.

`sure/memory/index.md` is built by the `pre_start` hook; on a fresh clone it
appears after the first run starts. If it is missing, use
`memory/bad_cases/README.md`. If nothing matches, use
`playbooks/failure_taxonomy.md` for classification instead of reading all bad
cases.

Entries marked `[provisional]` or `[disputed]` in the index were written by an
agent in an earlier run and not reviewed by a person; treat them as hints.

## Audit Record

Record what memory you actually read in `context_selection.json` under
`selected_references.memory` (paths, relative to the skill package for
`references/` files and to the repo root for `sure/memory/` files). The schema
allows no other memory field. Example:

```json
{
  "task_type": "asr",
  "selected_references": {
    "default": [
      "references/AGENTS.md",
      "references/memory/COMMON.md",
      "references/task_playbooks/ROUTING.md",
      "references/playbooks/env_ROUTING.md"
    ],
    "task_playbooks": ["references/task_playbooks/ASR.md"],
    "environment_playbooks": ["references/playbooks/env_uv.md"],
    "contracts": ["references/contracts/spec_validation.md"],
    "memory": [
      "references/memory/COMMON.md",
      "sure/memory/index.md",
      "references/memory/bad_cases/wrong_entrypoint.md"
    ]
  },
  "skipped_references": ["references/task_playbooks/TTS.md"],
  "rationale": "ASR model on uv; the launcher error matched the wrong_entrypoint entry"
}
```
