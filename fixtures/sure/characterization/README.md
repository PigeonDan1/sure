# SURE pre-refactor characterization

These fixtures freeze observable behavior before the SURE Core extraction. They are regression evidence, not a second workflow authority and not proof that a production artifact passed SURE validation.

`repository-baseline.v1.json` is generated by importing the six current state machines and checkpoint implementations. It records unit contracts, every one-step transition, terminal re-entry behavior, retry limits, schema profiles, and hashes of the implementation and characterization tests.

The four `legacy-*.fixture.*` files preserve the unversioned Pi run/state/event persistence shape and the `sure.run_result.v1` output shape. Their basenames intentionally differ from live `run.json`, `state.json`, `events.jsonl`, and `result.json` files.

Regenerate and verify the repository fixtures with:

```sh
npm run sure:characterize
npm run check:sure-characterization
```

The production reference catalog is a bounded metadata observation. It never copies weights or prediction payloads, and it refuses an output path that is lexically or physically inside the reference tree:

```sh
node --import tsx scripts/sure-characterization.ts reference \
  --root /hpc_stor03/project/oref/nfs \
  --output fixtures/sure/characterization/reference-snapshot.nfs-20260906.v1.json \
  --observed-at 2026-09-06T00:00:00+08:00
```

The checked-in snapshot is diagnostic historical evidence. Reproducible evaluation must still validate current bundle, runtime, dataset, inference protocol, scoring protocol, and execution receipt identities at the conformance boundary.
